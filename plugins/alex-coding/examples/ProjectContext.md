# Project Context

This optional file helps planning and implementation Agents understand this repository. Keep it concise; link to existing sources instead of copying them. Replace the prompts below with verified facts, or mark an unknown as undecided. Empty sections do not authorize the Agent to invent requirements.

## Purpose and stack

What does this project do? Which languages, runtimes and platform versions matter?

## Structure and constraints

Where does the important code live? Which architectural or compatibility boundaries must changes preserve?

## Authoritative documents

Where are requirements, accepted design decisions and delivery contracts kept? Link to the existing files; a suggested path is not proof that a document exists.

## Verification

Which commands run formatting, tests and builds? Which working directory or environment is required? What must be checked manually?

## Acceptance and delivery

Which outcomes require human acceptance? What reviewer, author identity and merge rules already apply? Reference existing repository instructions when they own these rules.

## Exceptions and open questions

Which project-specific restrictions or unresolved decisions affect current work? Include only relevant facts, not a running log of implementation history.

## Maintaining this context

Who can approve changes to these conventions? If a separate context PR or explicit human approval is required, state it here. Do not claim such a rule has been accepted merely because this example mentions it.
